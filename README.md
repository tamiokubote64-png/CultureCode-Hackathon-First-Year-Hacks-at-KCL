# Sonic Postcodes — local integration

This repository combines the existing **FastAPI visual-analysis backend** with the
existing **Streamlit UI**. In the default Streamlit view, a photograph is sent to
`POST /api/analyze` and the returned scores and explanations are displayed.
The original Echoframe environment explorer is preserved as an optional mode.

**Important:** The third music-generation stream is not yet part of this
integration. Showing musical parameters does not mean audio playback is working.

## Run both applications (Windows PowerShell)

From the repository root:

```powershell
git pull --ff-only origin main
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

Configure the **backend** locally if you want real OpenAI image analysis: copy
`backend/.env.example` to `backend/.env`, set your real `OPENAI_API_KEY` and
a supported `VISION_MODEL`. Never commit `backend/.env`.

Terminal 1, from the repository root (leave running):

```powershell
cd backend
python -m uvicorn app.main:app --reload --port 8000
```

Terminal 2, from the repository root (activate the same .venv if necessary):

```powershell
python -m streamlit run ui.py
```

Open **http://localhost:8501**, upload a photograph, and click **Analyse
photograph**. FastAPI can be tested independently at **http://127.0.0.1:8000/docs**.

To start on macOS/Linux, use `python3 -m venv .venv`, activate with
`source .venv/bin/activate`, and use the same Python commands afterward.

## How the applications communicate

```text
Browser
  -> Streamlit UI (ui.py; localhost:8501)
     -> ui_backend_client.py
        -> HTTP multipart POST http://127.0.0.1:8000/api/analyze
           -> FastAPI (backend/app/main.py)
              -> OpenAI Vision service (backend/app/vision.py)
           <- VisualAnalysis JSON
     <- UI renders grandeur, energy, brightness, density, warmth + explanations
```

The UI and backend do not import each other's internal application modules:
an HTTP endpoint is their stable integration boundary. The backend is the
**source of truth** for the five visual scores; the legacy explorer is separate
and must not be described as a genuine OpenAI analysis.

The UI uses `SONIC_API_URL` (default `http://127.0.0.1:8000`) to locate the
backend. Set this variable only if the API runs at a different address.

This integration expects successful responses of the form:

```json
{
  "scene": "A dramatic city street",
  "description": "Tall buildings dominate the perspective.",
  "scores": {
    "grandeur": 0.9,
    "energy": 0.6,
    "brightness": 0.7,
    "density": 0.8,
    "warmth": 0.3
  },
  "explanations": {
    "grandeur": "Towering facades create a monumental impression.",
    "energy": "A few visible cars suggest some activity.",
    "brightness": "Daylight illuminates the road.",
    "density": "Buildings fill most of the frame.",
    "warmth": "Cool grey tones dominate."
  }
}
```

These values are **illustrative** and are not generated by the UI. The backend
provides the real values for an uploaded photo.

## Testing and troubleshooting

From the repository root:

```powershell
python -m unittest discover -s tests -p "test_ui_backend_client.py" -v
cd backend
python -m pytest -v
```

These tests use mocks, not paid provider requests. A successful end-to-end
demo also requires one actual HTTP 200 from `POST /api/analyze`.

- **UI cannot connect:** Start FastAPI and verify `GET /api/health` on port 8000.
- **HTTP 503:** Read the backend message; check local OpenAI credentials,
  provider quota/billing or model access. Don't treat it as a UI bug.
- **HTTP 429:** Temporary rate limit; follow `Retry-After`.
- **HTTP 413:** The backend limits images to 5 MiB and 20 megapixels.
- **UI unchanged:** Ensure you pulled/checked out the integration branch
  or merged its pull request before testing.
- **Legacy mode:** Does not send the image to FastAPI; it retains the teammate's
  Claude/colour-estimate workflow and optional Anthropic key.
